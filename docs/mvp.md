

# ТЕХНИЧЕСКОЕ ЗАДАНИЕ

## Плагин MineGate

**Telegram ↔ Minecraft (Paper), MVP**

---

## 0. Общая цель

Разработать **Minecraft Paper-плагин**, который обеспечивает **двустороннюю синхронизацию чата** между сервером Minecraft и Telegram-группой **без привязки аккаунтов**, с поддержкой reply-контекста и выполнением кастомных серверных команд через Telegram.

Плагин:

* работает **без внешних сервисов**
* **сам** взаимодействует с Telegram Bot API
* использует **long polling**
* не блокирует main thread сервера
* стабилен при падениях Telegram / рестартах сервера

---

## 1. Поддерживаемая среда

### Minecraft

* Paper **1.21+**
* Java **17+**
* Adventure API (для hover / formatting)

### Telegram

* Telegram Bot API
* Получение обновлений через `getUpdates` (long polling)
* Webhook **не используется**

---

## 2. Архитектурные требования

### 2.1 Потоки исполнения

* Все сетевые операции Telegram выполняются **в отдельном потоке**
* Все операции с Bukkit API выполняются **только в main thread**
* Между Telegram и Minecraft используется **очередь сообщений**

### 2.2 Отказоустойчивость

* При недоступности Telegram:

  * сервер продолжает работать
  * сообщения из Minecraft **не теряют сервер**
* При рестарте сервера:

  * Telegram polling корректно пересоздаётся
  * webhook (если был) удаляется

---

## 3. Общая логика моста

### 3.1 Направления синхронизации

* Minecraft → Telegram
* Telegram → Minecraft

### 3.2 Защита от зацикливания

* Сообщения, отправленные ботом, **не обрабатываются повторно**
* Для этого используется:

  * source-флаг
  * либо hash-сигнатура сообщений

---

## 4. Формирование имён пользователей

### 4.1 Telegram → Minecraft

Имя отправителя определяется по приоритету:

1. `@username`
2. `first_name last_name`
3. `first_name`
4. `TelegramUser`

Формат в Minecraft:

```
[TG] <name>: <message>
```

### 4.2 Minecraft → Telegram

Используется **ник игрока** без попыток сопоставления:

```
⛏ <nickname>: <message>
```

---

## 5. Reply-контекст (обязательное требование)

### 5.1 Общий принцип

Reply реализуется **на уровне сообщений**, а не пользователей.

Плагин обязан хранить связь:

* Telegram `message_id`
* Minecraft сообщения (виртуальный id)

### 5.2 Telegram → Minecraft (reply)

Если пользователь в Telegram отвечает **на сообщение бота**, которое было сгенерировано из Minecraft:

В Minecraft сообщение отображается как:

```
@Shelby [в ответ Gen3is]: ща починю
```

#### Hover-текст на `[в ответ Gen3is]`

```
Gen3is: Шелби почини хуйню
```

### 5.3 Потеря контекста

Если оригинальное сообщение:

* отсутствует
* устарело
* не найдено

→ reply-индикатор **не отображается**, сообщение выводится как обычное.

---

## 6. Кастомные команды через Telegram

### 6.1 Назначение

Позволить выполнять **ограниченный набор серверных команд** из Telegram-чата, описанных в конфиге.

### 6.2 Формат конфига

```yaml
custom-commands:
  ping:
    need-player: true
    command: "ping %player%"
    description: "Пинг игрока"

  online:
    need-player: false
    command: "list"
    description: "Онлайн игроков"
```

### 6.3 Правила выполнения

* Команда доступна **только если описана в конфиге**
* `%player%` подставляется из аргументов Telegram-команды
* Выполнение происходит **от имени сервера**
* Результат команды:

  * перехватывается
  * форматируется
  * отправляется в Telegram ответом

### 6.4 Ограничения

* Максимальное количество строк вывода: **N (напр. 15)**
* Длина строки ограничена
* Команды вне списка — игнорируются
* Ошибки выполнения возвращаются текстом

---

## 7. Команды Telegram-бота (MVP)

Обязательный минимум:

* `/help` — список доступных кастомных команд
* `/online` — если описана в конфиге
* `/ping <player>` — если описана в конфиге

(реализация через кастомные команды допустима)

---

## 8. Системные события (минимум)

Плагин **может** (флагами конфига):

* отправлять join / quit
* отправлять death messages
* отправлять старт / остановку сервера

Формат:

```
⚙ Shelby зашёл на сервер
```

---

## 9. Конфигурация (обязательные параметры)

```yaml
telegram:
  token: "<BOT_TOKEN>"
  chat-id: "<CHAT_ID>"
  poll-timeout-seconds: 20

bridge:
  enabled: true
  read-only: false
  cooldown-ms: 1000
  max-message-length: 220

reply:
  enabled: true
  max-age-seconds: 3600
```

---

## 10. Ограничения MVP (осознанно)

В MVP **НЕ требуется**:

* привязка аккаунтов
* права Telegram-ролей
* inline-кнопки
* базы данных сложнее SQLite / in-memory
* web-интерфейс
* RCON

---

## 11. Критерии готовности (Definition of Done)

MVP считается готовым, если:

1. Чат стабильно синхронизируется в обе стороны
2. Reply из Telegram корректно отображается в Minecraft
3. Кастомные команды из конфига выполняются и возвращают результат
4. Сервер не лагает и не падает при проблемах с Telegram
5. Конфиг полностью управляет поведением плагина
6. Нет зацикливания сообщений

---

## 12. Итог

Это **не игрушка**, а минимально достаточный продукт:

* без лишней хуйни
* без архитектурных долгов
* с возможностью спокойно дорасти до полноценного bridge/staff-инструмента
